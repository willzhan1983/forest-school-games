# 森林学校 · 课间十分钟

浏览器里直接玩的**课间小游戏合集**，给小朋友做的。森林学校主题的第二个作品，和跑酷篇共用同一套角色 IP。

**在线玩：** <https://willzhan1983.github.io/forest-school-games/>

同系列跑酷篇：[forest-school-runner](https://github.com/willzhan1983/forest-school-runner) · <https://willzhan1983.github.io/forest-school-runner/>

---

## 三个小游戏

| 游戏 | 主角 | 玩法 |
|------|------|------|
| **接橡果** | 涂涂 Doodle（猫头鹰） | 橡果从树上往下掉，左右移动接住。连击越高单次加分越多（10 分起，每连击 +3，封顶 50），漏接扣一颗心 |
| **记忆翻牌** | 钱钱 + 涂涂 | 翻开卡片找相同的小动物。基础分按棋盘大小给（1000~1800），再按用时和翻牌次数扣分，保底 50 分 |
| **找不同** | 钱钱 + 涂涂 | 左右两幅森林图，找出不一样的几处。左右两边都能点，点对一处 +120，点错扣一次机会；全部找齐按剩余机会奖励（每颗心 +150），困难档额外 75 秒限时 |

> 「松鼠冲刺」已移除 —— 它的玩法（障碍迎面跑、跳/冲二选一）和同系列的《放学跑酷》重复了，留着是两个差不多的游戏。

每个游戏**独立记最高分**，档位也是每个游戏单独生效。

## 档位

**接橡果**是三档难度：

| 难度 | 接橡果 |
|------|--------|
| 简单 | 5 颗心 · 同屏最多 2 个 · 落得慢 |
| 普通 | 3 颗心 · 同屏最多 3 个 |
| 困难 | 2 颗心 · 同屏最多 4 个 · 落得快 |

**记忆翻牌**没有「难度」概念 —— 牌多就难，所以直接在菜单上选**棋盘多大**：

| 棋盘 | 张数 | 基础分 |
|------|------|--------|
| 4 × 3 | 12 张 | 1000 |
| 4 × 4 | 16 张 | 1200 |
| 5 × 4 | 20 张 | 1500 |
| 6 × 4 | 24 张 | 1800 |

**找不同**也是三档难度：

| 难度 | 找不同 |
|------|--------|
| 简单 | 3 处不同 · 9 个景物 · 5 次机会 · 不限时 |
| 普通 | 5 处不同 · 14 个景物 · 4 次机会 · 不限时 |
| 困难 | 7 处不同 · 18 个景物 · 3 次机会 · 75 秒限时 |

> 困难档除了景物更多、机会更少，还给部分差异加了**朝向翻转**（比如鸟和蝴蝶转个方向），更难一眼看出来。

档位选择在菜单页，每个游戏各记各的，选完会记住，下次打开还是它。

## 怎么玩

**电脑（键盘）**
- `1` `2` `3` 选游戏，`←` `→` 选档位（接橡果选难度 / 翻牌选棋盘），`空格` 开始
- 接橡果：`←` `→` 或 `A` `D` 移动
- 记忆翻牌：鼠标点卡片
- 找不同：鼠标点两幅图里不一样的地方（左右都行）
- 任何时候按 `Esc` 回菜单

**手机 / 平板（触屏）**
- 菜单页：点卡片直接开始，点档位条切换
- 接橡果：手指按住屏幕左右拖，涂涂跟着走
- 记忆翻牌：点卡片
- 找不同：手指点两幅图里不一样的地方

横屏玩最舒服，竖屏也能玩（会弹一条提示，4 秒后自己消失，不挡画面）。

## 其他

- 背景音乐在菜单页就响，一路延续到游戏和结算页不中断；左上角音符按钮随时开关，**开是绿底、关是灰底带红斜杠**，一眼能看出来
- 音乐开关和难度都记在本地，关掉网页下次还在
- 最高分也是本地记的（浏览器 localStorage），换设备不通用

## 技术

单个 `index.html`，**零外部依赖** —— 没有 CDN、没有库、没有图片文件，两个角色立绘以 base64 内联，断网也能玩。

- Canvas 2D 手绘全部画面（角色、背景、卡片、动物脸都是代码画的）
- Web Audio API 实时合成音效和 BGM（C 大调五声音阶，32 步 A/B 句，13.4 秒循环），没有音频文件
- 自动适配窗口大小和屏幕像素密度，键盘 + 触屏双套操作

## 开发

`index.html` 是构建产物，手改会被覆盖。源码在 `src/`：

```
src/p1.html ~ p4.html   四个片段，按序拼接
src/cat.b64.txt         钱钱立绘 base64
src/owl.b64.txt         涂涂立绘 base64
src/g-spot.html        找不同（每个 g-*.html 是一个小游戏）
src/merge.js            拼接 + 注入立绘，产出 index.html
src/syntax.js           抽出内嵌 script 供 node --check 校验
tests/test.js           主测试套件（Puppeteer + 无头 Chrome，含像素采样）
tests/test-anim.js      动画过程逐帧追踪
```

```bash
node src/merge.js                 # 重新构建 index.html
node src/syntax.js && node --check src/_extracted.js
python3 -m http.server 8931       # 起本地服务
NODE_PATH=<puppeteer-core 所在 node_modules> TARGET_URL=http://127.0.0.1:8931/index.html node tests/test.js
```

新增一个小游戏，分三步：

1. 在 `src/p2.html` 的 `GAMES` 里加一条（`mode:'level'` 用三档难度、`mode:'grid'` 用棋盘尺寸）。
2. 新建 `src/g-<id>.html`，在文件末尾**自注册** —— 遍历 `GAMES` 找到自己的 id，把 `start / update / draw / tap / banner` 挂上去；需要暴露给测试的内部对象挂到 `window.__fsmExtras`（主循环所在的 `src/p4.html` 会在最后把它并进 `window.__fsm`）。
3. 在 `src/merge.js` 的 `PARTS` 数组里插一行，**必须放在 `p3` 之后、`p4` 之前**（p4 收尾整个 IIFE，并且 `__fsmExtras` 的并入口就在 p4）。

主循环、输入分发、开场横幅都是按 id 查表的，加新游戏不用再改 `if/else` 主循环。

> 浏览器规定声音必须由用户先点一下画面才能响，所以**打开页面后先点一下**，音乐就来了。这是所有网页游戏的共同限制，不是本游戏的问题。
