### P0-1 接橡果漏接好橡果扣命【已修复 PR #24】
- 位置：`src/p3.html` 行 289-305 `updateAcorn()` 的 `n.y > H + 30` 分支
- 现状：`if(isGood) { combo=0; lives-- }`
- 体测数据 (`game-balance-audit.md`)：相同玩家水平，普通档撑满率从「良好」6% → 改后预期 63%
- 改法（已写在体检报告里）：漏接好橡果只断连击，不扣命；接到坏东西才扣命
- 锚定：`lives` 三档分别 5/3/2，`game-balance-audit.md` 推荐 `lives=3` 全档
- 同步：「漏掉好橡果扣命」也是「惩罚玩家做不到的事」（同屏最多 4 个，只能接 1 个）
- 工作量：5 行 + 一个 T 重测

### P0-2 记忆翻牌计分公式基线算错【已修复 PR #25】
- 位置：`src/p3.html` 行 706-710 `updateMemory()`
- 现状：`flipPenalty = (flips - n) * 6` + `timePenalty = (el/60)*4`
- 根因：`n = 牌数`，但完美记忆最少要翻 `1.5n` 次（先翻完摸位置，再花 `n/2` 次配对）
- 体测数据：4×3 完美玩法被罚 36 分（18 翻 - 12 牌 = 6×6），永远在 base 之下
- 改法（已写在体检报告）：
  ```js
  flipPenalty = max(0, flips - Math.round(n * 1.5)) * 12
  Game.score = max(50, base - flipPenalty)   // 去掉 timePenalty
  ```
- 收益：完美可拿满分（目标可达）、区分度 +20~25%、去掉一个孩子看不见却一直在扣的分
- 工作量：3 行 + 一个 T 重测

### P0-3 找不同不限时档「隐形时间罚」【已修复 PR #26】
- 位置：`src/g-spot.html` 行 417 `spotScore()`
- 现状：`timePen = floor(el / 60 * 4)` 对所有档生效
- 触发条件：`c.time:0`（easy / normal）也照样扣
- 用户感知：孩子慢慢找完，结算分比预期低一截，看不到任何扣分说明 —— 觉得「游戏莫名其妙」
- 改法：`if(c.time > 0) timePen = floor(Spot.el / 60 * 4);`（或干脆 hard 档单独 timePen，easy/normal 不变）
- 双向选项：（A）不去掉，UI 显示一个计时器让规则可见；（B）去掉，但失去张力来源。推荐 B
- 工作量：1-3 行 + 1 测试

### P0-4 找不同开局送 base 分【已修复 PR #26】
- 位置：`src/g-spot.html` 行 410 `startSpot()` 末尾 `Game.score = c.base`
- 现状：一进游戏就是 1700，找对一处 +120 相对反馈仅 7%；「我已经有分了」削弱成就锚点
- 改法：`Game.score = 0` 开局，base 留在 `spotScore()` 末尾加上去
- 注意：`spotScore` 是实时刷新的（updateSpot 调用），不是只在结算算 —— 改完要注意 UI 上每个 find 之后会不会闪（不会，因为 120 多）
- 工作量：1-2 行

## P1 · 反馈通道（影响留存）

### P1-1 结算页缺星级评价（独立 P0，但已在体检报告）
- 现状：只能看「新纪录！」或「最高分 X」
- 问题：新纪录触发概率单调递减；玩 100 次和第 1 次反馈感一样
- 改法：5 个游戏结算页统一加 1~3 星，星级按绝对分数划（如满分 60% = 3 星、30% = 2 星、其它 = 1 星）
- 工作量：5 个 `endGame` 调用 + 一个 `drawResult()` 改造 + 1-2 测试。中等

### P1-2 分数尺度不统一
- 接橡果：0→1400（加分制）
- 翻牌：1800→50（扣分制）
- 找不同：1700→3000
- 打地鼠：累计加分，45 秒撑满率
- 拼图：900/1200/1500（满分制）
- 改法：跟 P1-1 一起做，星数 = 「相对满分的百分比」统一
